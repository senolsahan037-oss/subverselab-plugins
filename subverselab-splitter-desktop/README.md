# SubverseLab Splitter — desktop

The JUCE plugin: HT-Demucs stem separation running on the listener's own
machine, as Standalone, VST3 and AU. Restored to the development area on
2026-08-26 from `Archive/legacy/2026-08-25_splitter-juce-source.zip` after the
web tool replaced it on subverselab.com, so that the two can be compared and
this one kept as the fallback if the hosted version proves too expensive to run.

## Building

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release -DCMAKE_OSX_ARCHITECTURES=arm64
cmake --build build -j8
```

JUCE is fetched by CMake. **ONNX Runtime is vendored in `_deps/onnxruntime` and
pinned to 1.18.0**, which is the version `.github/workflows/build-windows.yml`
downloads for the Windows build. Do not upgrade one without the other: the two
platforms would compile against different headers, and nothing would say so
until something crashed at runtime. Ask before bumping it.

`Resources/htdemucs.onnx` is 302 MB and lives in Git LFS
(`68d0bf16428ef66e692cdff8a9ccf28f1ef3f69440d57e58605a4cc55fcc5e74`). The web
tool keeps a byte-identical copy at
`../subverse-splitter-web/models/htdemucs.onnx`.

## Checks

```bash
./build/test_overlap                                   # the window plan
./build/test_analysis_artefacts/Release/test_analysis <file.wav>   # tempo and key
```

`test_analysis` is checked against the web Splitter rather than against its own
output: both report 136.0 BPM and B minor (Camelot 10A) for the same file.

## What changed on 2026-08-26

**Separation was leaving a tick every 7.8 seconds.** The run loop stepped
through the file in consecutive model windows and concatenated the output.
HT-Demucs denoises a whole window at once and its edges are its least certain
region, so butt-joining two of them left a step at each join — measured at
**35.4x** the surrounding signal on real music, worst in the vocal. It now
overlaps windows by 25 % and cross-fades them under a triangular weight, which
brings it to **2.4x**, indistinguishable from ordinary signal. Costs about a
third more model runs. See `Source/OverlapAdd.h` and `test_overlap.cpp`.

**The model was being fed raw samples.** Demucs is trained on input normalised
to zero mean and unit variance from the mono reference; a quiet master and a
loud one were landing in different parts of its input space. Normalised in,
denormalised out.

**BPM and key detection did not exist.** The product page advertised "built-in
BPM/key detection" from the first release; the C++ contained no mention of
tempo, key, chroma or Camelot. The claim had been carried over from the Python
prototype and never implemented. It is in `Source/Analysis.cpp` now, and the
reading appears in the header while separation is still running — it takes
about 30 ms where separation takes minutes.

Two windows, not one: onsets want time resolution (4096 samples), pitch wants
frequency resolution (16384). A semitone at 65 Hz spans 3.8 Hz and a
4096-sample window has 10.8 Hz bins, so a bass note and its neighbour landed in
the same bin and the key came out shifted — the estimator answered C major,
B minor and B minor on the bass, harmony and vocal stems of one track. With the
long window and a semitone filterbank it answers B minor on all three, which is
what librosa says about the same audio.

**Stems were written as 16-bit.** Separation output routinely exceeds the
input's peak, so that clipped material which never clipped going in. Now 24-bit.

**An instrumental stem was added** — the mix minus the vocal estimate, not the
sum of the other three. Those are different signals: the four stems do not
account for every sample, and summing them drops whatever the model could not
place.

**The palette was Tailwind's defaults** — teal-500, amber-500, indigo-500,
sky-500, slate-800, under a navy gradient. All of it is now in `Source/Theme.h`,
and the stem colours are the same five Arrangement GPS and the web Splitter use,
so a drum track is one colour across the platform. The header mark is
byte-identical to the web tool's.

**Per-stem level and timeline scrubbing.** The mixer had only M and S, so the
only way to hear less of a stem was to hear none of it, and the timeline drew a
playhead that did nothing when clicked.

**The Dock icon was a stock "S".** Orange, teal, blue and navy ribbons on white,
sharing nothing with the brand — in a Dock beside anything else of ours it read
as a different company's app. It is now the same mark the web tool and the
plugin header carry, on the brand ground, generated by
`scripts/generate_icon.py`.

**Two images were compiled in and never drawn.** `background.png` and
`loading_workers.png` — 1.1 MB of AI-generated artwork, including a cartoon of
construction workers untangling cables captioned "AUDIO UNTANGLE PROJECT" — were
loaded into `juce::Image` members at startup and never reached a `paint` call.
The background is painted from `Theme.h` and the loading state is animated in
code, so there had never been anything for them to do. Both deleted.

## The post-separation screen, 2026-08-26

Rebuilt after looking at it. `screencapture` cannot photograph the window — a
terminal has no macOS Screen Recording permission, so it hands back the desktop
wallpaper instead — so `test_ui_snapshot` renders the editor offscreen through
`createComponentSnapshot`, which needs no permission and can be pointed at any
state:

```bash
./build/test_ui_snapshot_artefacts/Release/test_ui_snapshot <audio.wav> out.png
./build/test_ui_snapshot_artefacts/Release/test_ui_snapshot --empty out.png
```

It runs a real separation, so it also exercises the model path end to end. The
binary is not a bundle, so symlink the model beside it once:
`ln -s "$PWD/Resources/htdemucs.onnx" build/test_ui_snapshot_artefacts/Release/`.

What the snapshots showed:

**The tempo and key were on screen and invisible.** They were drawn into the
header's left corner, under `loadedFileLabel` — a child component, painted after
its parent, over the same 300 pixels. Moved to four labelled cells in a strip of
their own below the header. The strip measures zero until there is a reading, so
the empty window still gives the drop target everything.

**`paint()` and `resized()` disagreed about the row.** One reserved 120 px on
the right for the controls, the other trimmed 180 px off the waveform, so every
row carried a 60 px hole and the four did not line up. Both now read one
`StemLayout` namespace, and the controls sit in a single horizontal row so the
same control is at the same x in every stem.

**The waveforms were built from RMS divided by a hardcoded 0.35.** RMS is
average energy, and a drum stem is mostly silence with events in it, so the row
flattened to a line; the 0.35 meant how tall a stem drew was decided by a
constant rather than by the audio. Peak per block now, 400 points, each stem
scaled against its own peak up to 6x — capped, so a stem holding almost nothing
still reads as almost nothing rather than being stretched to look full.

**The playhead only existed on the transport bar.** Someone auditioning a
separation is looking at the waveforms; it is drawn on each of them now.

**The scrub bar was invisible at the start of a track.** A four-pixel dark strip
whose filled portion is zero-width at 0:00 — nothing on screen at the moment you
most want to find it. It has a track, a fill, a handle, and the elapsed and
total times at either end. Its geometry lives in `timelineBounds()`, read by both
the painting and the hit-testing, since those drifting apart is how it came to
draw in one place and answer clicks in another.

**The instrumental was written to disk and never mentioned.** It is offered from
the transport rather than as a fifth mixer lane, because it is not one — it
already contains the drums, bass and other stems, so playing it alongside them
would double everything but the vocal.

## Open

The Standalone shows JUCE's yellow "Audio input is muted to avoid feedback
loop" bar because the plugin declares a stereo input bus. `processBlock` never
reads it — playback is fed from the stem mixer and the separation is offline —
so the bus is decoration, and removing it would remove the bar. It would also
move the plugin from an effect slot to an instrument slot in a DAW, which is a
decision about existing sessions rather than about tidiness. Not changed.
